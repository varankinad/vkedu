## Выводы

При последовательной загрузке задержка каждого запроса прибавляется к предыдущим, поэтому время растёт линейно с числом ID. При параллельной загрузке неблокирующие задержки перекрываются, и общее время близко к задержке одного запроса.

Для 14 ID теоретическое ожидание составляет около `14 * 1500 = 21000` мс против `1500` мс. Это расчётные ориентиры; фактические результаты приведены в таблице. Случайная оценка от 3.0 до 5.0 не меняет фиксированную задержку. Кеширование не используется.

Контрольный JVM-замер использует 14 существующих локальных приложений, чтобы набор оставался воспроизводимым. UI не ограничен этими ID и обрабатывает весь текущий каталог сервера; при проверке 16.11.2026 каталог содержал 41 приложение.

Неограниченный параллелизм реализован намеренно для упражнения. Для реального сервера потребовались бы отдельные ограничения с учётом его пропускной способности и лимитов запросов.
